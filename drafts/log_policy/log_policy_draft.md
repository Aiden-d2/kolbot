# 로그 정책 틀 (초안, 261102)

- 사용자가 정한 것은 **[정함]**, Claude 제안은 **[제안]**, 고를 것이 있으면 **[선택]**으로 적었다.
- 근거 자료: `log_inventory.md`(호출 목록), `log_flow_check.md`(흐름 점검).

---

## 1. 로그 4가지의 역할

| 로그 | 역할 | 남는 곳 |
|---|---|---|
| 콘솔 | **흐름 전체**. 이 파일 하나로 클라이언트 시작부터 매니저 종료까지 무슨 일이 있었는지 안다 **[정함]** | 매니저 콘솔(색) + 전 프로필 공유 파일 하나(날짜로 나누지 않음) **[정함]** |
| print | **상세 기록**. 원래 d2bs 콘솔처럼. 지금 trace의 영구 줄과 머리 위 글자의 사건을 받는다 **[정함]** | 게임 화면 콘솔, d2bs 로그(프로필·날짜별, 엔진이 시각을 붙임) |
| trace | **임시 검증용만** **[정함]** | `_cache/trace/trace-<프로필>-<날짜>.txt` |
| 머리 위 글자 | 화면에서 지금 하는 일. 매 틱 반복되는 표시는 여기에만 둔다 **[정함]** | 남지 않음 |

- 콘솔 줄은 print에 한 벌 남기지 않는다(`OOG.js:38` `[console]`, 걷어냄) **[정함]**
- 콘솔에 가는 사건의 상세(지금 trace `[Quit] 이유: 상세`, `[Error] …`)는 print로 간다 **[정함]**

## 2. 줄 모양

### 2-1. 공유 콘솔 파일

```
[2026/11/02 17:45:54] <a1> <분류> 내용 (지역 x,y)
```

- 시각·프로필은 아이템 로그와 같은 모양 **[정함]**
- `<분류>` 칸: 색이 파일에 남지 않으므로 넣는다. `printToConsole`에 넘어오는 색으로 한 곳에서 정한다 **[제안]**

| 분류 | 색 | 들어가는 것 |
|---|---|---|
| `Flow` | 7 | 게임 입장, 구간 시작·끝 등 흐름 (3절) |
| `Item` | 8, 5 | 퀘스트 아이템 `!!!`, `[Hired]`, `[Socket]`, `[Runeword]`, 큐브 |
| `Exp` | 4 | 경험치 줄 |
| `Quit` | 0 | 조기 종료 이유 |
| `Red` | 9 | 치킨·사망·핑·멈춤 |
| `Error` | 10 | 잡힌 오류·치명 오류 |
| `OOG` | 10 | 게임 밖 줄(`(loc N)`). 10을 오류와 나누려면 `OOGLog.print`가 따로 알려야 함 |

- 매니저 콘솔 줄은 지금처럼 색으로 구분하고 분류 칸은 넣지 않는다 **[제안]**

### 2-2. print

```
내용 (지역 x,y)
```

- 시각·프로필은 엔진이 붙인다(d2bs 로그 `[MM/DD/YY HH:MM:SS] D2BS <번호>:`).
- `(지역 x,y)`는 모든 줄에 붙인다 **[정함: 지역과 좌표는 필요]**. 게임 밖은 `(loc N)`.
  - 예외로 둘지 **[선택]**: 구간 헤더, 게임 경계, `[Error]`(지금 trace 규칙은 이 셋에 위치를 붙이지 않음).
- 색 코드(`ÿc`)는 넣지 않는다. d2bs 로그에 글자로 남는다 **[제안]**
- 줄 안의 `area:` + 번호, `in 지역` 표기는 지운다(끝의 위치와 겹침) **[제안]**

### 2-3. 문장 모양 (print·콘솔 공통) **[제안]**

| 종류 | 모양 | 예 |
|---|---|---|
| 진행 | `주체: 일` | `Den: start`, `Town: chores start`, `changeAct: 2 -> 3` |
| 실패 | `주체 failed: 이유` | `Smith failed: moveTo`, `useUnit failed: timeout iter:2 dist:7` |
| 재시도 | `주체 retry N/M: 이유` | `hire retry 2/5`, `WP retry 3/12: menu not opened` |
| 측정·값 | `키:값` 띄어쓰기로 이어 붙임 | `dist:7 ping:120` |
| 게임 밖 | 지금 규칙 그대로 `사건: 대상 - 처리 (loc N)` | `Create game failed - wait 30s` |

- `주체`는 구간 이름(`Den`), 함수 이름(`moveTo`, `useUnit`), 스레드(`TownChicken`) 중 사람이 알아볼 이름.
- 대괄호 꼬리표(`[hire]`, `[WP]`, `[SafeTele]` …)는 `주체:`로 바꾼다. 남길 대괄호는 지금 콘솔에 있는 것(`[Hired]`, `[Socket]`, `[Runeword]`, `[Reset]`)만.
- `FAILED`, `Can't`, `cannot`, `not found`만 쓴 줄은 `주체 failed: 이유`로 맞춘다.

### 2-4. trace

- 지금 모양 그대로(`[MM/DD/YY HH:MM:SS] 내용 (지역 x,y)`).
- 줄 끝 메모에 handoff 번호와 제거 조건을 반드시 적는다 **[제안]**

## 3. 콘솔에 남길 흐름 사건 **[제안]**

"콘솔 하나로 흐름 파악"을 위해 넣을 것. **굵게** 적은 것이 지금 없는 것이다.

| 단계 | 사건 | 누가 | 지금 |
|---|---|---|---|
| 게임 밖 | **클라이언트 시작** (`Start: D2BotLead/Follow`) | 모두 | 없음 |
| 게임 밖 | 로그인·키·렐름 문제, 방 만들기·입장 실패, 크래시 뒤 대기 | 모두 | 있음 |
| 게임 밖 | **방 만들기 `Create game: 이름`** | 리더 | print만 |
| 게임 밖 | **방 입장 `Join game: 이름`** | 팔로워 | print만 |
| 게임 밖 | 팀 대기, 휴식 | 리더 | 있음 |
| 게임 시작 | **게임 입장 `Game: 이름 [레벨]`** | 모두 | trace만 |
| 게임 시작 | 퀘스트 아이템 `!!! …`, 새 캐릭 `=== START ===` | 지금대로 | 있음 |
| 구간 | **구간 시작** `=== X ===` | **[선택]** 리더만 / 모두 | 리더만, 구간 끝에 |
| 구간 | **구간 끝 `X: done` / `X failed: 이유`** | **[선택]** 리더만 / 모두 | 리더의 헤더가 끝 표시를 대신함 |
| 구간 | **팀 맞추기 대기가 길어질 때** (예: 30초 넘으면 `okCount: wait 이름,이름`) | 모두 | 시간 초과 때만 |
| 구간 | **액트 이동 `changeAct: 2 -> 3`** | **[선택]** 리더만 / 모두 | 머리 위 글자만 |
| 구간 | 용병 고용, 소켓, 룬워드, 큐브 | 지금대로 | 있음 |
| 끝 | 조기 종료·치킨·핑·오류·멈춤 | 모두 | 있음 |
| 끝 | **죽음 `Died (지역 x,y)`** (그 순간) | 모두 | 다음 게임에 `You died in last game` |
| 끝 | 경험치 줄 | 모두 | 있음 |
| 끝 | 리더 플레이 시간 요약, 팔로워 `Game finished` | 지금대로 | 있음 |

- 구간 줄을 모두가 찍으면 8명 × 구간 수만큼 늘어난다. 리더만 찍고 팔로워는 "팀과 다른 일"(실패, 대기 초과, 이탈)만 찍는 안이 짧다 **[제안]**
- 레벨 업은 경험치 줄 `[Level N]`로 알 수 있어 넣지 않는다 **[제안]**

## 4. print에 남길 것 **[제안]**

| 들어오는 것 | 처리 |
|---|---|
| 지금 print 199곳 | 2절 모양으로 맞춤. 오류 줄(`Config.js` `Error:`, `AutoBuildThread` `Something broke!` 등)도 print에 둔다(상세 기록이 print로 모이므로) |
| trace 영구 줄 (실패·재시도·진행·콘솔 상세) | print로 옮기고 2절 모양으로 |
| 머리 위 글자 중 한 번씩 일어나는 사건 | print로 (`tpReady`, `changeAct`, 마을 일, 웨이, 퀘스트 진행 등) |
| 아이템마다 찍히는 머리 위 글자 | 아이템 로그와 겹치면 넣지 않음. 겹치지 않는 것(골드·열쇠 줍기, 칸 옮기기, 문)은 넣지 않음 **[선택]** |
| **새로 넣을 것** | 마을 일 시작·끝(`Town: chores start/done`), 팀 맞추기 도착(`okCount: all in Ns`) |

## 5. 구현 방식 **[제안]**

- **print용 함수 하나**를 둔다. 하는 일: 위치 `(지역 x,y)` 붙이기, 게임 밖이면 `(loc N)`, 색 코드 지우기.
  - 새로 만드는 것: `Misc` 함수 1개(예: `Misc.log(msg)`). 기존 print 호출을 이 함수로 바꾼다.
  - 이보다 단순한 안: 호출마다 `+ " (" + Misc.where() + ")"`를 붙이는 것. 호출 수(수백 곳)만큼 같은 코드가 생겨 택하지 않음.
- **콘솔 공유 파일 쓰기**는 `D2Bot.printToConsole` 한 곳에 넣는다. 아이템 로그와 같은 `Misc.fileAction` 덧붙이기.
  - 파일 경로 **[선택]**: `_cache/trace/Console.txt`(아이템 로그와 같은 폴더) 등.
- 머리 위 글자와 print를 같이 찍는 자리는 두 줄을 그대로 둔다(함수로 묶지 않음) **[제안]**

## 6. 정할 것 목록

1. 콘솔 분류 칸 이름과 묶음(2-1).
2. print 위치 예외(헤더·게임 경계·`[Error]`).
3. 문장 모양(2-3)을 이대로 할지.
4. 구간 시작·끝, 액트 이동을 콘솔에 리더만 / 모두.
5. 새 흐름 사건(클라이언트 시작, 방 만들기·입장, 게임 입장, 죽음, 팀 대기 길어짐)을 넣을지.
6. 아이템마다 찍히는 머리 위 글자의 처리.
7. print 함수 1개를 새로 만들지(5절).
8. 공유 파일 경로.
