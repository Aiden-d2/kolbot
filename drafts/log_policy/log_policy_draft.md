# 로그 정책 (초안 v2, 261102)

**261102 사용자: 나머지 제안 모두 수용. 문장 다듬기는 나중. 한 번에 진행 희망(코드 실행 중 아님, 로컬 사본 있음).**

- **[정함]** = 사용자 결정, **[제안]** = Claude 제안(이 문서의 대부분), **[보류]** = 나중에.
- 근거: `log_inventory.md`(호출 목록), `log_flow_check.md`(흐름 점검). v1에서 바뀐 곳은 사용자 답(261102)을 반영했다.

---

## 1. 역할

| 로그 | 역할 | 남는 곳 |
|---|---|---|
| 콘솔 | 흐름. 리더가 팀의 흐름을 찍고, 모든 프로필은 자기 끝(종료·치킨·오류·경험치)과 문제만 찍는다 **[정함: 흐름은 리더만]** | 매니저 콘솔(색) + 공유 파일 `_cache/trace/Console.txt` **[정함: _cache/trace 안]** |
| print | 상세 기록. 분석에 필요한 것은 모두 여기. 프로필마다 남는다 | 게임 화면 콘솔, d2bs 로그 |
| trace | 임시 검증용만 **[정함]** | `_cache/trace/trace-<프로필>-<날짜>.txt` |
| 머리 위 글자 | 매 틱 반복되는 화면 표시만 **[정함]**. 한 번씩 일어나는 사건은 print로 옮기고 머리 위 글자는 지운다(print가 게임 화면 콘솔에도 보이므로 겹침) **[제안]** | 남지 않음 |

`_cache/trace`에 남는 파일: `ItemLog.txt`, `Console.txt`, 임시 trace. `ScriptErrorLog.txt`는 없앤다(8절).

## 2. 줄 모양

### 2-1. 공유 콘솔 파일 (1번 답)

```
[2026/11/02 17:45:54] <a1> <Quit> Malus failed (Forgotten Tower 12345,6789)
```

분류는 `printToConsole`이 받은 색과 게임 안/밖으로 한 곳에서 정한다. 호출 68곳은 고치지 않는다.

| 분류 | 정하는 기준 | 들어가는 것 |
|---|---|---|
| `OOG` | 게임 밖(`me.ingame` 아님) | 로그인·키·방·크래시 줄 |
| `Flow` | 색 7 | 게임 입장, 구간 끝 |
| `Item` | 색 8, 5 | 퀘스트 아이템, 용병 고용, 소켓, 룬워드, 큐브 |
| `Exp` | 색 4 | 경험치 줄 |
| `Quit` | 색 0(기본) | 조기 종료 이유, 플레이 시간 요약 |
| `Red` | 색 9 | 치킨·사망·핑·멈춤 |
| `Error` | 색 10, 게임 안 | 오류 |

- 게임 밖 판정을 쓰면 회색(10)을 오류와 게임 밖으로 나누려고 `OOGLog`를 고칠 필요가 없다.

### 2-2. print (2번 답)

```
내용 (지역 x,y)
```

- 위치는 **게임 안에서만** 붙인다. 게임 밖 줄은 붙이지 않는다 **[정함]**(콘솔 게임 밖 줄은 지금처럼 `(loc N)`).
- 위치를 붙이지 않는 게임 안 줄: 게임 경계 `=== [게임 이름] ===`, 구간 헤더 `=== [X] ===` **[제안]**
- 색 코드는 넣지 않는다(d2bs 로그에 글자로 남음).
- 줄 안의 `area:` + 번호, `in 지역`은 지운다(끝의 위치와 겹침).

### 2-3. 문장 (3번 답: 통일만, 다듬기는 나중) **[정함]**

| 종류 | 모양 |
|---|---|
| 진행 | `주체: 일` |
| 실패 | `주체 failed: 이유` |
| 재시도 | `주체 retry N/M: 이유` |
| 값 | `키:값` 띄어쓰기로 |
| 게임 밖 | 지금 규칙 `사건: 대상 - 처리` |

대괄호 꼬리표는 `주체:`로 바꾼다. 남기는 대괄호는 콘솔의 `[Hired]`, `[Socket]`, `[Runeword]`, `[Reset]`.

### 2-4. trace

- 지금 모양 그대로. 줄 끝 메모에 handoff 번호와 제거 조건을 적는다.

## 3. 콘솔 흐름 (4번 답: 흐름은 리더만, 분석에 필요한 것은 print)

| 사건 | 콘솔 | print |
|---|---|---|
| 게임 밖 문제(로그인·키·렐름·방 실패·크래시) | 모두(지금대로) | - |
| 팀 대기·휴식 | 리더(지금대로) | - |
| **게임 입장** | 리더 `Game: 이름` (새) | 모두 `=== [게임 이름] ===` (trace에서 옮김) |
| 구간 시작 | 없음 | 모두 `=== [X] ===` (지금대로) |
| **구간 끝** | 리더 `X: completed` **[정함: done 대신 completed]** (지금 리더가 구간 끝에 찍는 `=== X ===`를 바꿈) | 실패는 모두 `X failed: 이유` |
| 퀘스트 아이템, 고용, 소켓, 룬워드, 큐브 | 모두(지금대로) | 지금대로 |
| 조기 종료·치킨·핑·오류·멈춤 | 모두(지금대로) | 상세(`이유: 상세`)를 print로 |
| **죽음(그 순간)** | 모두 `Died` (새) | - |
| 경험치, 플레이 시간 요약, `Game finished` | 지금대로 | 지금대로 |

- 콘솔 `=== X ===`가 "끝"인데 print `=== [X] ===`가 "시작"인 혼동이 없어진다.

## 4. 새로 넣는 사건 (5번 답)

| 사건 | 어디 | 이유 | 넣지 않으면 |
|---|---|---|---|
| 게임 입장 `Game: 이름` | 콘솔(리더) | 콘솔 파일에서 게임 경계가 보임. 지금은 trace에만 있어 trace를 임시로 돌리면 사라짐 | 콘솔 파일에서 어느 줄이 어느 게임인지 모름 |
| 게임 경계 `=== [게임 이름] ===` | print(모두) | 지금 trace에서 하던 일. 분석 때 프로필별 게임 나누기 | print만으로는 게임 경계를 모름 |
| 죽음 `Died` | 콘솔(모두, 빨강) | 지금은 다음 게임 시작 때 경험치 감소로만 추정(`default.dbj:69`, 라이프 치킨이 꺼져 있으면 안 찍힘). 어디서 죽었는지 남지 않음 | 사망 위치·시각을 모름 |
| 구간 끝 `X: completed` | 콘솔(리더) | 3절 | - |
| 팀 맞추기 대기 `okCount: waiting a3,a5` | print(모두), 한 번(예: 30초 넘을 때) | `Party desynced` 원인 분석(누가 늦었는지는 지금도 quit 상세에 있음, 늦어지기 시작한 시각이 없음) **[보류 가능]** | 시간 초과 전 상황을 모름 |

넣지 않는 것 **[제안]**

- 클라이언트 시작: d2bs 로그에 엔진 줄이 있고, 재시작 이유는 게임 밖 줄(`- restart`, `Crash:`)로 남음.
- 방 만들기·입장 성공: 게임 입장 줄로 충분.
- 액트 이동: 구간 헤더로 알 수 있음. 실패는 `changeAct N failed`(조기 종료)로 남음.
- 마을 일 시작·끝, 레벨 업: 흐름에서 빠져도 분석에 막히는 곳이 없었음(레벨은 경험치 줄에 있음).

죽음을 어디서 감지할지는 구현 때 정한다(지금 `me.dead`를 보는 스레드 코드가 없음, ToolsThread 검색 0).

## 6. print 함수 (7번 답)

`Misc.print(msg)` 1개를 새로 만든다 **[제안]**

- **하는 일**: ① 게임 안이면 끝에 `(지역 x,y)`, 밖이면 붙이지 않음 ② 색 코드 지움 ③ `print`
- **목적**: print 모양을 한 곳에서 정한다. 지금 print 199곳 + trace에서 옮길 약 90곳.
- **효과**: 위치 붙이기와 색 지우기가 호출마다 반복되지 않는다. 나중에 모양을 바꿀 때 이 함수 하나만 고친다.
- **만들지 않으면**: 약 290곳에 `+ " (" + Misc.where() + ")"`를 붙이고, 게임 밖에서 부를 수 있는 곳은 따로 가려야 한다.
- 게임 경계·구간 헤더처럼 위치를 붙이지 않는 줄은 `print`를 그대로 쓴다.

## 7. 걷어내기 **[제안]**

| 대상 | 이유 |
|---|---|
| `[console]` print 한 벌(`OOG.js:38`) | 공유 파일로 대체 **[정함]** |
| `ScriptErrorLog.txt` 쓰기(`Misc.errorReport`) | 파일에만 있는 것은 `Stack:` 한 줄뿐. 스택을 print로 옮기면 남길 이유 없음 |
| `debugLog(me.profile)`(`D2BotLead.dbj:374`, `D2BotFollow.dbj:185`), `Misc.debugLog`(호출 0) | d2bs 로그에 프로필 이름 한 줄만 남김. 파일 이름·콘솔 파일에 프로필이 이미 있음 **[정함: 지움]** |
| 채팅 `say`(Starter 3곳) | 안 쓰임 **[정함: 지움]** |

남기는 것 **[정함]**

- AutoBuild `log`·`Verbose` print: 오류·오작동을 볼 때 켜서 쓰는 진단 기능.
- 측정기(숫자패드 5), 키 입력 디버그(숫자패드): 키를 눌러야만 동작, 보통 게임에는 안 찍힘. 새 정책에서는 콘솔 대신 print로 보낼지 형식 정리 때 본다.
- 매니저 아이템 탭(`Misc.logItem` → `D2Bot.printToItemLog`): 사용자가 아이템을 그래픽으로 보는 주요 화면. `logItem` 9곳 모두 바로 옆에 같은 동작의 `itemLogger`가 있어(261102 확인) 분석은 `ItemLog.txt`로 한다.

매니저 화면(콘솔 색, 아이템 탭 그래픽)은 사람이 보는 곳, 파일(`Console.txt`, `ItemLog.txt`, d2bs 로그)은 분석과 매니저가 꺼졌을 때의 기록이다 **[정함]**

## 8. `ScriptErrorLog.txt` (8번 답)

- `Misc.errorReport`가 남기는 것: 콘솔(회색) + trace `[Error]` + 파일. 파일에만 있는 것은 오류 객체의 `Stack:` 줄.
- 제안: 콘솔·`[Error]` 상세·`Stack:`을 print로 남기고 파일 쓰기를 지운다.

## 9. 작업 순서 **[제안]**

1. 공유 콘솔 파일 + 분류 칸 + `[console]` 한 벌 제거(`OOG.js` 한 곳).
2. `Misc.print` 추가, trace 영구 줄을 print로 옮기며 2절 모양으로 맞춤(파일별로 나눠서).
3. 머리 위 글자 중 사건을 print로 옮김.
4. 콘솔 흐름 줄 바꿈(구간 끝, 게임 입장, 죽음).
5. 걷어내기(7절).
6. CLAUDE.md 4절, `log_guide.md`, `docs/log_types.md` 다시 쓰기.

각 단계는 수정 목록으로 승인받아 진행한다.
