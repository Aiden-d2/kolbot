# 인수인계

새 대화는 이 문서부터 읽는다. 절과 흐름은 `CLAUDE.md` 5절을 따른다.
- 1절 `진행 여부 대기`: 문제(사례) / 확인된 것 / 판단에 필요한 것
- 2절 `구현 검토·수정 대기`: 확인된 것 / 가설 / 구현안(대상 함수, 수정 규모) / 검증 방법
- 3절 `인게임 검증 대기`: 바꾼 것(커밋) / 검증 방법 / 결과(로그 묶음별)
- 흐름: 1 → 2(진행 결정) → 3(수정 완료) → 코드 노트(검증 통과). 3 검증 실패는 실패 사례를 붙여 2로. 기각은 `rejected.md`. 같은 내용은 한 항목에만, 옮길 때 `옛 N-N`. 지운 번호는 다시 쓰지 않는다.

trace 파일은 게임 PC의 `kolbot/_cache/trace/`에 있다. 사용자가 올려 주면 분석한다(방법은 `log_guide.md`, 결과는 `log_results.md`).

**마지막으로 분석한 로그**: 261025 묶음(10/24 13:47 ~ 10/25 08:47, 시작 시각 전까지 병합된 main `5cbb612`+`67f30e4`로 본다, 실행 중 파일 변경 없음(사용자), `log_results.md` 261025). **다음 사이클**은 261025 `81d5b43`(3-27 벨트 넣기 위치) 병합 뒤 main으로 돈다. 그 코드에는 3-32(`789d80d`·`aafbe50`), 3-33(`f26ef73`), 3-34(`d93027d`), NTIP 기어 tier 게이트(`cc75f66`·`9b94436`)도 처음 들어간다.

### 1-15. 상점에서 큐빙 재료(크래프트 매직 베이스 등)를 사지 않음 (`Town.shopItems`, `Pickit.checkItem`, 사용자 261024)
- **문제**(사용자): 크래프트의 매직 베이스는 상점에서 충분히 살 수 있는데, 상점은 판정 결과 1만 사서 큐빙 재료는 사지 않는다.
- **확인된 것**(코드)
  - `Town.shopItems`는 `Pickit.checkItem` 결과가 1인 것만 산다. 노말 난이도는 벨트(itemType 19)만, 나이트메어·헬은 `Config.MiniShopBot`이 켜졌을 때만 산다(기본값 `false`, 빌드에서 바꾸는 곳 없음).
  - `Pickit.checkItem`은 `Cubing.checkItem`이 참이면 nip 판정보다 먼저 2(큐빙 재료)를 돌려준다 → 크래프트 베이스(nip이 원하지 않는 매직 아이템, `validItem`의 크래프트 조건 `result === 0`)처럼 재료에 해당하는 아이템은 2가 되어 상점이 사지 않는다.
  - 갬블(`Town.gamble`)·감정(`Town.identify`)은 얻은 아이템이 2이면 `Cubing.update()`를 부른다(재료가 들어오는 자리). 상점에는 재료가 들어오지 않아 업데이트도 없다.
  - `shopItems`를 부르는 곳: `buyPotions`, `repair`(그 안의 호출 조건은 읽지 않음).
- **판단에 필요한 것**: 진행할지. 한다면 상점에서 살 큐빙 재료의 범위(크래프트 베이스만인지, 레시피 전체인지), 살 때 골드 조건, 산 뒤 `Cubing.update()`.

### 1-16. 벨트에 아무 등급 물약이나 들어감 (`Town.clearBelt` 벨트 넣기, 사용자 261025)
- **문제**(사용자): 인벤토리 물약을 벨트에 넣을 때 등급을 보지 않아 낮은 등급도 들어간다. 원래 동작이라 당장 고칠 것은 아니고, 나중에 맞지 않는 등급은 버리기로 넓히면 된다(사용자 261025).
- **확인된 것**(코드)
  - 벨트 넣기(261025 `81d5b43`부터 `clearBelt` 끝, 원본 kolbot은 `clearInventory` 앞)는 물약을 종류(hp·mp·rv)로만 골라 이름이 맞는 열에 넣는다. 등급은 보지 않는다.
  - `buyPotions`는 빈 칸만 채우므로, 낮은 등급이 칸을 차지하면 그 칸에 상점 최고 등급을 사지 않는다. 게임이 벨트 안에서 어떤 등급을 먼저 마시는지는 확인하지 않음.
  - 상점 최고 등급은 `Town.getPotion(npc, type)`(상점 품목을 5 → 1등급 순으로 찾음)으로만 알고, `buyPotions`가 상점을 연 뒤에만 부른다. `clearBelt`는 heal 앞, 상점을 열기 전이다.
  - 등급 기준이 이미 두 곳에 있다: `X.nip` 138~148줄(회복·마나 1등급 노멀 1~2막, 2등급 노멀 1~3막, 3등급 노멀 1~4막, 4·5등급 항상)과 `clearBelt`의 노멀 마나 규칙(2막 mp1, 3막 mp1·mp2를 벨트에서 버림). 두 기준이 한 막씩 어긋난다(nip은 2막에서 mp1, 3막에서 mp2를 줍는다).
- **판단에 필요한 것**: 진행할지. 한다면 기준(① 같은 게임에서 연 상점의 막별 최고 등급을 기록해 씀 — 새 상태 1개, 게임 첫 방문엔 적용 안 됨, ② 막·난이도 고정 표 — 상점 데이터 필요(2-13), ③ nip 판정 `Pickit.checkItem`이 0이면 넣지 않음 — 새 상태 없음), 넣지 않은 물약을 버릴지, nip과 `clearBelt` 마나 규칙의 어긋남을 어느 쪽으로 맞출지.

### 2-22. 소켓 우선 tier와 tier 줄 품질 하한 노말 이상 (X.nip·빌드 nip tier 줄, 사용자 261023·261024, 옛 1-12)
- **문제**(사용자): 소켓 보석(`docs/code/Pickit.md` socketTargets)으로 노말 장비에 보석을 넣으면 실제로는 tier가 높아지는데, 지금은 판정할 수 없다.
- **사용자 설계**(261024, 진행 결정. 구현 논의는 남음)
  - 소켓 tier는 능력치가 아니라 우선순위다. 처음엔 아무 장비나 입고(tier 1), 소켓이 있는 것을 먼저 입어 보석 작업으로 능력치를 올리고 tier 11 이상으로 간다. 소켓 + 능력치로 tier 11을 주는 것은 아니다.
  - 소켓 수마다 tier 하나. 최대 소켓: 헬름 3, 아머 4, 방패 4, 무기 6.
  - tier 11 이상은 지금 능력치 줄 그대로 두고 품질 하한만 `[quality] >= magic` → `[quality] >= normal`.
  - 대상: X.nip 헬름·아머·방패, 빌드 nip 무기·클래스 전용 아이템. 소켓이 없는 벨트·장갑·부츠·반지·목걸이는 대상 아님.
  - tier 번호는 로직만 정한다. 기존 번호와 겹치면 한 단계 미루는 식이고, 구조는 나중에 바꿀 수 있다.
  - 3-32(옛 2-15, 착용 중인 베이스로 룬워드·펀치)와 같이 작업한다. 소켓이 많은 룬워드 베이스를 입으면 보석 대상에서 빠지고(`socketTargets`가 룬워드 베이스 제외) 재료로도 쓰이지 않아 빈 소켓으로 착용만 하게 되기 때문.
- **확인된 것**
  - 판정: tier 목록은 tier 높은 순으로 정렬되고(`NTItemParser.dbl` `NTIP_Lists.tier.sort`) 맞는 첫 줄을 쓴다 → 맞는 줄 중 가장 높은 tier. 소켓 줄과 능력치 줄을 같이 둘 수 있다.
  - `[sockets]`(stat 194, 전체 소켓 수)는 nip에서 쓸 수 있다(`NTItemAlias.dbl`).
  - 보석 능력치는 아이템 능력치에 합산된다(사용자 확인 261024).
  - 지금 tier 구조: 장비 종류마다 tier 1만 `[quality] >= normal`, tier 11부터 `[quality] >= magic`. 예외로 B.WCRY 무기 tier 11~20은 `[quality] >= normal`.
  - 지금 tier 2~10을 쓰는 줄: X.nip 벨트 2·3(베이스 이름). 빌드 nip 무기는 노말 이상을 데미지 점수로 tier 1~5(P.FIST 1~10). B.WCRY·M.HYBR는 2~10 없음.
  - 요구 힘·민첩이 모자라면 tier 0(`NTIP.GetScore`, 판정의 tier 단계).
- **구현 논의 필요**(Claude 정리, 결정 아님)
  1. tier 구조와 단계: 부위별 소켓 tier 번호(소켓 0 = tier 1부터 헬름 4단계, 아머·방패 5단계, 무기 7단계). 무기 7단계와 비워 둘 칸. 번호를 미루면 tier 11 이상, 빌드 파일의 `TierGoal`, `[tier] == N`을 직접 쓰는 룬워드·유니크 줄도 같이 밀리는지.
  2. 무기 묶음: 빌드 무기는 이미 노말 이상을 데미지 점수 tier 1~10으로 나눈다. 소켓 우선과 데미지 점수 중 무엇을 먼저 볼지, 아니면 묶음(데미지 단계 × 소켓 수)으로 할지.
  3. 클래스 전용 아이템 범위: 빌드별 목록(오브·완드, 클로, 바바리안 헬름, 드루이드 펠트, 네크로맨서 머리, 팔라딘 방패, 아마존 활·재블린 등)과 각 종류의 최대 소켓 수.
  4. 소켓 줄 품질: `>= normal`이면 능력치 점수가 낮은 매직·레어도 소켓 tier를 받는다. 노말·슈페리어만 둘지.
  5. 룬워드: 소켓 줄에 `[flag] != runeword`를 넣을지(룬워드 전용 tier 줄이 없는 룬워드가 소켓 tier를 받음). 옛 1-12의 룬워드 검토(사용자)와 같은 내용.
  6. 줍기 증가: 소켓 줄에는 능력치 조건이 없어 tier 1을 입고 있으면 소켓 있는 노말 장비를 모두 주워 입는다(재료 베이스 포함). 3-30 홀드(베이스 이름 기준)와의 관계.
  7. 용병 줄(`[merc]`)은 이 설계 범위 밖인지.
- **구현안**: 위 논의 뒤 정한다. 수정은 nip만(X.nip + tier 줄이 있는 빌드 nip 14개), 줄 수는 구조가 정해진 뒤.
- **같이 할 것**(사용자 261025): 기어 tier 게이트(`[body] < 21`, `[mercbody] < 21`, `docs/code/NTItemParser.md`, PR #90·#91)로 nip 재료 줄을 바꾸는 작업을 이 nip 수정에 같이 한다. 기어 기능의 인게임 검증도 이때 3절에 넣는다.
  - 재료 줄의 기어 조건 숫자(`< 21`, `< 41` 등)는 tier 번호다 → 위 1번에서 tier 번호를 미루면 같이 고친다.
  - 기어 조건은 재료 줄(일반·수량 묶음)에만 쓴다. tier·용병 줄에 쓰면 조건이 빠지고 trace `NTIP: gear tier ignored on tier/merc line`이 남는다.
- **검증 방법**: 검토에서 정한다.
