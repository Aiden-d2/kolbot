# Attack 흐름 해설 (공부용)

- 대상: `libs/Attack.js`의 `Attack.clear`와 `Attack.setPosition`. 두 함수가 이번 리팩터링의 본체다.
- 줄 번호는 브랜치 `claude/attack-docs`의 현재 파일 기준이다. 주석 처리된 옛 코드(`//`로 시작)는 건너뛰고 읽으면 된다.
- 다른 파일의 변경은 한두 줄씩이라 맨 끝 부록에 한 줄씩만 적었다.
- 읽는 순서: 0절 흐름도 → 1절 clear → 2절 setPosition → 3절 두 함수의 대화(`tick`) → 4절 실제 상황 따라가기

---

## 0. 한눈에 보는 흐름도

```
AutoSmurf / Pather ──► Attack.clear(range, must)
                          │
                          ├─ [입구] 인자 정리, 스킬 검사, 변수 준비                  (53~107)
                          │
                          └─ while (true)  ── 한 바퀴 = 한 "틱" ──────────────────── (110~452)
                               │
                               ├─ 0. 사망 / 소왕 / TownCheck                       (111~121)
                               ├─ 1. 스캔: 몬스터 전체를 읽어 목록(entries)에 합류    (123~173)
                               ├─ 2. 정리: 소탕 기준점 이동 + 죽은·벗어난 몹 제거      (175~260)
                               │        └ 가장 가까운 대상(nearest) 계산
                               ├─ 3. 칠 게 없으면: 사라진 보스 찾기 / 보스 대기 / 종료 (262~299)
                               ├─ 4. 대상 선택: 거리순, 목줄(leash), 306 스킵         (301~321)
                               ├─ 5. 공격: ClassAttack.doAttack(대상)                (357~364)
                               │        └ 직업 파일 ──► Attack.setPosition(대상, 사거리, 0x4)
                               │                          │  (위치 선정 + 이동. 결과를 tick에 기록)
                               │                          └► Skill.cast (시전하면 tick.cast = true)
                               └─ 6. 결과 판정: 버릴지, 다시 칠지, 계속 칠지            (366~451)
                          │
                          └─ [출구] 줍기, afterAttack, 상자                         (453~469)
```

**핵심 구조 한 줄 요약**
- clear는 "누구를 칠지, 언제 버릴지"를 정한다.
- setPosition은 "어디에 설지"를 정하고 이동한 뒤, 결과를 `Attack.tick`에 남긴다.
- clear는 다음 단계에서 그 기록을 읽고 판단한다.

## 1. Attack.clear(range, must)

### 1-0. 호출 형태 (AutoSmurf 기준)

| 호출 | 뜻 |
|---|---|
| `clear(25)` | 호출 위치 반경 25 안의 몹을 소탕 (일반 몹 = SWEEP) |
| `clear(0, 156)` | classid 156(안다리엘)을 반드시 처치 (MUST). 지역 소탕 없음 |
| `clear(0, "이름")` | 이름이 같은 몹을 MUST로 |
| `clear(0, [540, 541, 542])` | 배열 중 하나라도 맞으면 MUST |
| `clear(0, {box: {...}})` | 박스 안의 모든 몹을 MUST로 |
| `clear(35, 이름)` | 보스 MUST + 보스 주변 35 소탕 (`getBoss`만 사용) |

- **MUST:** 반드시 죽인다. 어떤 이유로도 버리지 않는다. 예전 `clearList + scanList`의 역할이다.
- **SWEEP:** 소탕 대상이다. 조건이 맞으면 버린다. 예전 `clear`의 역할이다.

### 1-1. 입구 (53~107줄)

| 줄 | 하는 일 | 왜 |
|---|---|---|
| 54~56 | 게임 준비 대기 | 예전과 같음 |
| 58~64 | range 기본값 25, 숫자 아니면 throw | 예전과 같음 |
| 66~68 | `AttackSkill[1]` 또는 `[3]`이 -1이면 false | 예전과 같음 |
| 70~78 | **스킬 보유 검사.** 설정된 스킬을 실제로 안 배웠으면 콘솔 메시지 + `D2Bot.stop()` + false. 500(소환 네크)은 예외 | 오토빌드 오류로 모든 몹을 스킵하던 문제 |
| 80~87 | 변수 준비 (아래 표) | |
| 89~93 | must가 박스인데 range > 0이면 range를 0으로 | 박스 밖 몹이 섞이지 않게 |
| 95~98 | HP 스킵 기록(`gidSkip`) 초기화. 지역이 바뀌었거나 마지막 스킵 위치에서 40 넘게 떨어지면 | 예전과 같음 |
| 101 | 보스 대기 시간(`mustPendingUntil`). id·이름·배열 호출이면 지금부터 `5 × (ping×2+100)`ms | 보스가 소환 직후 안 잡힐 때 바로 끝나지 않게 |
| 103~107 | `drop()` 함수: 대상을 목록에서 빼고, 이번 호출에서 다시 받지 않게 `dropped`에 적음. 로그 `[AC] drop 이유` | 예전 `monsterList.shift()`에 해당 |

**변수 사전**

| 변수 | 뜻 |
|---|---|
| `entries` | 지금 처리 중인 대상 목록. 키는 gid, 값은 `{unit, must, retry, idle, casts, ...}` |
| `dropped` | 이번 호출에서 버린 gid. 스캔할 때 다시 들어오지 못하게 막는다 |
| `orgx, orgy` | 소탕 기준점. 처음엔 호출 위치이고, 보스를 따라 움직일 수 있다(1-4) |
| `spec` | must를 정리한 것. `{ids: [...]}` 또는 `{box: {...}}` 또는 null |
| `mustSeen` | 보스를 한 번이라도 봤는지 |
| `mustAlive` | 이번 틱에 살아 있는(또는 대기 중인) 보스가 있는지. 위험 반경을 켤지 정한다 |
| `nearest` | 가장 가까운 대상 |
| `nearestLive` | 가장 가까운 대상 중 deferred(뒤로 보낸 보스)가 아닌 것 |
| `lostEntry` | **이름이 헷갈리는 변수.** 1-4에서는 "기준점으로 따라갈 보스", 1-5에서는 "시야에서 사라진 보스"로 두 번 재사용한다 |
| `castTotal` | 이번 호출의 실제 시전 수. 선공 주기와 종료 처리에 쓴다 |

### 1-2. 루프 시작: 사망, 소왕, TownCheck (110~121줄)
- 죽었으면 false로 끝낸다.
- 소 레벨(39)에서 소왕이 가까이 있으면 false로 끝낸다. 호출한 쪽이 소 레벨을 중단한다.
- TownCheck 설정이 켜져 있으면 마을 확인을 한다.

모두 예전과 같다.

### 1-3. 스캔 (123~173줄): 매 틱 몬스터를 전부 새로 읽는다
예전 clear는 호출할 때 한 번만 목록을 만들었다. 지금은 **매 틱 다시 읽어서** 새로 나타난 몹이나 보스도 합류시킨다.

```
mustAlive = (보스를 아직 못 봤고 대기 시간 중) 또는 (목록에 보스가 있음)         (125~133)

getUnit(1)로 몬스터를 하나씩:
  ├ checkMonster 실패 (죽음, 무적 등)             → 건너뜀                       (139)
  ├ tick.monList에 추가 (setPosition이 위협 계산에 씀)                              (143)
  ├ 이미 목록에 있거나 이번에 버린 몹              → 건너뜀                       (145)
  ├ must에 맞음                                  → MUST로 합류 (lastPos 기록)     (149~156)
  ├ 기준점에서 range 안이 아니고,
  │ (보스가 있을 때 나에게서 10 안)도 아님          → 건너뜀                       (158~162)
  ├ 1단 확정 제외: HP 스킵 기록 있음 / skipCheck 실패 / 먹히는 스킬 없음
  │                                              → dropped에 적고 건너뜀         (165~169)
  └ 통과                                          → SWEEP으로 합류                (171)
                                                   (range 밖인데 들어왔으면 danger = true)
```

- **위험 반경(danger):** 보스를 처리하는 호출에서는 range가 0이어도, 나에게서 10 안의 몹은 SWEEP으로 받는다. 보스를 치는 동안 붙은 몹에게 맞지 않으려는 장치다.
- **hpMark:** HP 스킵 판정의 기준 HP다. 합류할 때 기록한다(1-8).

### 1-4. 정리 (175~260줄)

**(a) 소탕 기준점이 보스를 따라감 (181~199줄)**
- 조건: range > 0이고 must가 id·이름·배열일 때만. 지금은 `getBoss`의 `clear(35, 이름)` 하나뿐이다.
- 목록의 보스 중 나에게 가장 가까운 보스를 고른다(`lostEntry`).
- 그 보스가 보이면 `lastPos`를 현재 좌표로 갱신한다. 안 보이면 이전 틱의 `lastPos`가 그대로 남는다.
- 기준점(`orgx, orgy`)을 그 `lastPos`로 옮긴다.
- 보스가 죽어 목록에서 빠지면 이 블록이 더 이상 기준점을 바꾸지 않는다. 그래서 죽은 자리에 고정되고, 호출 위치로 돌아가지 않는다.
- 보스를 한 번도 못 봤으면 목록에 보스가 없으므로 기준점은 호출 위치 그대로다.

**(b) 목록 정리 + 가장 가까운 대상 찾기 (201~260줄)**

```
목록의 각 대상:
  MUST
    ├ 안 보임 (시야 밖, 다른 지역)
    │   ├ 내가 lastPos 5 안에 와 있는데도 안 보임 → 목록에서 삭제 (죽었거나 멀리 감) (211~216)
    │   └ 아니면 lost 표시, mustAlive 유지                                         (218~221)
    ├ checkMonster 실패 (죽음)                    → 삭제                          (224~228)
    ├ 박스 MUST인데 박스 밖으로 나감               → 삭제                          (230~234)
    └ 정상: lost 해제, lastPos 갱신, mustAlive = true                             (236~238)
  SWEEP
    ├ checkMonster 실패                           → 삭제                          (240~244)
    └ danger면 나에게서 10 밖 / 아니면 기준점에서 range 밖 → 삭제                    (246~250)
       (삭제는 dropped가 아니라서, 다시 범위에 들어오면 다음 스캔에 합류 가능)

남은 대상 중 가장 가까운 것 → nearest, deferred가 아닌 것 중 가장 가까운 것 → nearestLive  (253~259)
```

### 1-5. 칠 대상이 안 보일 때 (262~299줄)
`nearest`가 없으면(보이는 대상이 하나도 없으면):
1. **lost 표시된 보스가 있으면:** 마지막 위치(`lastPos`)로 `moveTo`한다. 이 탐색을 최대 3번까지 하고, 넘으면 포기하고 삭제한다(284~298).
2. **보스를 아직 못 봤고 대기 시간 중이면:** 잠깐(`ping + 50`ms) 쉬고 다시 스캔한다(275~279).
3. **둘 다 아니면:** 루프를 끝낸다(281). 이게 정상 종료다.

### 1-6. 대상 선택 (301~321줄)
- **기본은 거리순:** `nearestLive`를 고르고, 없으면(모두 deferred) `nearest`를 고른다(303).
- **목줄(leash, 305~314):** 고른 대상이 MUST가 아니고 나에게서 10보다 멀면, 25 이상 떨어진 보스가 있는지 본다. 있으면 그 보스로 바꾼다. 보이는 보스만, deferred는 제외한다. 즉 가까이 붙은 몹이 없을 때만 멀어진 보스를 쫓는다.
- **카오스 StormCaster(316~321):** 108 지역, 보스가 아닌 306, 나와 0x4로 막혀 있으면 버린다. 예전 규칙과 같다.
- 323~355줄은 주석 처리된 옛 게이트다. 판정은 setPosition으로 옮겼다(2-3 참고).

### 1-7. 공격 (357~364줄)
- `tick`을 초기화한다: `cast = false`, `moved = false`, `fail = null`, `must = 대상이 MUST인지`.
- `ClassAttack.doAttack(대상, castTotal % 10 === 0)`을 부른다. 두 번째 인자는 선공(preattack)을 할 차례인지다.
- 직업 파일이 doAttack 안에서 setPosition으로 자리를 잡고, `Skill.cast`로 시전한다. 그 과정에서 `tick`이 채워진다.

### 1-8. 결과 판정 (366~451줄): 위에서부터 차례로, 걸리면 다음 틱으로

| 순서 | 조건 | SWEEP | MUST |
|---|---|---|---|
| ① (367~384) | doAttack이 2 반환 (먹히는 스킬 없음) | 버림 (`noskill`) | 뒤로 보냄(`deferred`). 다른 대상이 없을 때만 잠깐 대기 |
| — (386) | 2가 아니면 | | deferred 해제 (면역이 풀렸을 수 있음) |
| ② (388~396) | `tick.fail == "unreachable"` (setPosition이 갈 자리 없다고 함), NoSkipArea 밖 | **즉시 버림** (`unreachable`) | flash만 하고 계속 |
| ③ (398~411) | 결과 0 또는 `tick.fail` 있음 (이동 실패 등) | retry +1, flash. 5번째에 버림 (`retry`) | retry +1, flash. 5번째에 0으로 되돌리고 계속 |
| ④ (413~425) | 결과 1인데 `tick.cast`가 false (시전 안 함) | idle +1. **5번 연속이면 버림** (`idle`) | idle +1. 5의 배수마다 flash |
| ⑤ (427~430) | 실제로 시전함 | retry·idle 0으로, 시전 수 +1 | 같음 |
| ⑥ (432~434) | 근접 스킬(사거리 4 미만)이고 시전 10회마다 | flash | 같음 |
| ⑦ (436~451) | **HP 스킵** (SWEEP만, NoSkipArea 밖): 시전 5회 동안 HP가 20% 미만으로 줄면 | `gidSkip`에 기록하고 버림 (`hp`). 20% 이상 줄었으면 기준 HP를 새로 잡음 | 해당 없음 |

- `drop`으로 버린 대상은 이번 clear 호출이 끝날 때까지 다시 받지 않는다.
- clear는 이동 중 경로 노드마다, 또는 대기 루프에서 반복해서 불리므로, 다음 호출에서 다시 잡힐 수 있다.
- **flash:** 서버와 위치를 다시 맞추는 패킷이다. 막힘이나 판정 불일치를 풀려고 보낸다.

### 1-9. 출구 (453~469줄)
- `finally`: `tick.monList`와 `tick.must`를 비운다. 루프가 어떻게 끝나든(return 포함) 반드시 실행된다.
- 실제 시전이 1회 이상이면 아이템을 줍고(range가 0이면 기본 반경) `afterAttack`을 부른다.
- range > 0이면 기준점 주변 `min(range, 15)` 안의 상자를 연다.
- true를 반환한다.

### 1-10. 보조 함수 (472~526줄)
| 함수 | 역할 |
|---|---|
| `mustSpec(must)` | 인자를 `{ids: [...]}` / `{box: ...}` / null로 정리한다. 숫자나 이름 하나도 배열로 감싼다 |
| `mustMatch(spec, unit)` | 박스면 좌표가 안에 있는지, 아니면 classid나 이름이 맞는지 본다 |
| `hasUsableSkill(unit)` | 이 몹에게 먹히는 설정 스킬이 하나라도 있는지(저항 기준) 본다. 스캔 때 SWEEP 1단 제외에 쓴다 |

## 2. Attack.setPosition(unit, distance, coll, minDist)

직업 파일이 "이 대상을 사거리 `distance`에서 칠 수 있는 자리로 가라"고 부르는 함수다. `coll`은 "대상이 보인다"를 판단할 충돌 플래그이고, 보통 0x4다.

### 2-0. 흐름도

```
setPosition(unit, distance, coll)
 ├ 판정 (998~1017)
 │   moveNeeded = 사거리 밖 or 대상이 안 보임        → "접근"
 │   scoring   = 회피 조건 (Dodge 켜짐, 사거리 ≥ 9, HP 조건, Baal 243 아님)
 │   둘 다 아님 → true (그 자리에서 공격)
 │   회피 조건인데 주변 위협 0이고 접근도 아님 → true
 │
 ├ 링 만들기 (1019~1066)
 │   반지름: distance, distance-5, distance-10, ... (5 미만 제외)
 │   각 링에서 "대상→나" 방향(각도 0)부터 좌우로 5칸 간격 후보
 │
 ├ 구역 루프 (1071~1171): 정면(각도 ≤ 90) 먼저, 못 찾으면 후면(90~180)
 │   ├ 후보마다 위협 수 계산 (회피 조건일 때만)
 │   ├ 정렬: 바깥 링 → 각도 작은 순 → (접근이면) 위협 적은 순
 │   ├ 후보 검사 (정렬 순서대로, 처음 통과하는 자리 채택)
 │   └ 곧게 갈 자리가 없고 우회 후보만 있으면 → 우회 판정
 │
 └ 이동과 반환 (1173~1232)
     채택된 자리 → walkTo / teleportTo / moveTo(45 초과)
     우회 허용   → moveTo
     아무것도 없음 → false, tick.fail = "unreachable"
```

### 2-1. 판정 (985~1017줄)
| 줄 | 내용 |
|---|---|
| 986~988 | 대상이 무효면 false |
| 990 | 걷기 도착 허용 거리 `minDist` (기본 3) |
| 999 | **moveNeeded (접근 필요):** 나와 대상 거리 > distance, 또는 나↔대상이 coll로 막힘 |
| 1000 | **scoring (회피 채점):** `Dodge.Enabled` 이고, 스킬 사거리 ≥ `Dodge.Range`(9)이고, HP% ≤ `Dodge.HP`이고, 대상이 Baal(243)이 아님 |
| 1003~1005 | 둘 다 아니면 true. **이동이 필요 없으면 아무 검사도 안 한다.** 사거리 안에서 칠 수 있는 몹을 우회 판정으로 버리지 않는 이유가 여기 있다 |
| 1010~1017 | 회피 채점이면 지금 자리의 위협 수(`baseline`, 반경 9 안 몹 수, 불장판 포함)를 센다. 0이고 접근도 아니면 true |

- **접근:** 아직 칠 수 없는 상태라, 칠 수 있는 자리로 가는 이동이다.
- **회피:** 이미 칠 수 있지만, 위협이 더 적은 자리로 옮기는 이동이다.

### 2-2. 링 만들기 (1019~1066줄)
- `radii = [distance, distance-5, distance-10, ...]`, 5 미만은 뺀다. 사거리 링은 항상 넣는다.
  - 예: 사거리 20 → 20, 15, 10, 5 / 사거리 9 → 9 / 사거리 3 → 3
- `build(lo, hi)`: 각 링 위에서, 대상→나 방향을 0도로 두고 좌우로 번갈아(0, +a, -a, +2a, ...) 호 길이 5칸 간격으로 후보를 만든다. 각도가 `lo` 초과 `hi` 이하인 것만 만든다.
  - 정면: `build(-1, 90)` (0~90도)
  - 후면: `build(90, 180)` (90~180도). 정면에서 못 찾았을 때만 만든다(비용 절약).

### 2-3. 구역 루프 (1071~1171줄): 핵심

**(a) 위협 계산 (1076~1087)**
- 회피 조건일 때만 후보마다 반경 9 안의 몹 수를 센다.
- 텔레 회피에서는 45 넘는 후보를 뺀다(한 번에 가는 짧은 이동이어야 하므로).

**(b) 정렬 (1089~1098)**

| 모드 | 순서 |
|---|---|
| 접근 | **바깥 링 → 각도 작은 순 → 위협 적은 순** |
| 회피 | 바깥 링(대상에서 먼 쪽) → 각도 작은 순 |

- 바깥 링부터 보므로, 사거리 끝에서 칠 수 있으면 그 자리를 먼저 쓴다. 안쪽 링은 바깥 링에서 못 찾았을 때 쓴다. 이전 setPosition도 사거리 링을 먼저 봤다.
- 순서가 "어디로 갈지"를 정하고, 위협은 동점일 때만 본다.

**(c) 후보 검사 (1100~1137): 정렬 순서대로 위에서부터**

| 순서 | 검사 | 떨어지면 |
|---|---|---|
| 1 (1103) | 회피인데 위협이 지금 자리(baseline)보다 적지 않음 | 다음 후보 |
| 2 (1107) | 착지 가능: 텔레 `checkSpot(0x1)`, 걷기 `getCollision & 0x1` | 다음 후보 |
| 3 (1111) | 그 자리에서 대상이 보임: `CollMap.checkColl(대상, 자리, coll)` | 다음 후보 |
| 4 (1115) | 접근이면 불장판이 아닐 것 | 다음 후보 |
| 5 (1119~1122) | **SWEEP 접근 + 텔레:** 나→자리가 0x4로 트여 있을 것 (나에게서 보이는 자리) | 다음 후보 |
| 6 (1124~1132) | **걷기:** 나→자리 직선이 0x5로 트여 있을 것. 막혔으면 채택하지 않고, 아래 조건이면 "우회 후보"(`pathCand`)로 첫 하나만 기억: 접근이고, MUST이거나 나→자리가 0x4로는 트임(보이지만 0x1에 막힌 자리) | 다음 후보 |
| 통과 (1134) | 채택(`choice`) | 루프 종료 |

- 5와 6이 예전 clear의 **Angle 게이트**에 해당한다. 벽(0x4) 너머 자리는 SWEEP의 후보가 되지 못한다. 그래서 벽 너머 몹은 갈 자리가 없어 "도달 불가"가 된다.

**(d) 우회 판정 (1139~1156): 곧게 갈 자리가 없고 우회 후보만 있을 때**
- **MUST:** 길이와 상관없이 우회를 허용한다(`pathOk = true`).
- **SWEEP:** 예전 clear의 **Detour 게이트**에 해당한다.
  - `getPath`로 **나→대상** 걷는 경로를 구한다.
  - 경로 길이(노드 수 × 5)가 나→대상 직선 거리 × `DetourPath`(4) 이하면 허용한다.
  - 호출 한 번에 한 번만 계산한다(`detourOk`에 저장). 넘으면 `[SP] detour` 로그를 남긴다.
- 허용되지 않았고 아직 정면이면, 후면 구역을 이어서 본다(곧게 갈 후면 자리가 있을 수 있음).

### 2-4. 이동과 반환 (1173~1232줄)

| 상황 | 이동 | 반환 | tick |
|---|---|---|---|
| 채택 자리 있음, 걷기 | `walkTo` | 성공 true / 실패: 접근이면 false, 회피면 true | 성공 `moved`, 접근 실패 `fail = "moveFailed"` |
| 채택 자리 있음, 텔레 45 이내 | `teleportTo` | 위와 같음 | 위와 같음 |
| 채택 자리 있음, 텔레 45 초과 | `moveTo` (여러 번 텔레) | 위와 같음 | 위와 같음 |
| 회피인데 채택 자리 없음 | 없음 | true (그 자리에서 공격) | 없음 |
| 접근, 우회 허용 | `moveTo` (우회 후보로) | 성공 true / 실패 false | 실패 `fail = "moveFailed"` |
| 접근, 갈 자리 없음 | 없음 | false | `fail = "unreachable"` |

**반환값 규칙:** false는 **접근이 실패했을 때만** 나온다. 회피가 실패해도 true를 돌려서 그 자리에서 공격하게 한다.

## 3. clear와 setPosition의 대화: `Attack.tick`

setPosition과 직업 파일은 반환값(0/1/2)만으로는 "왜 실패했는지"를 clear에 알릴 수 없다. 그래서 `Attack.tick`이라는 공용 메모를 쓴다.

| 필드 | 누가 쓰나 | 누가 읽나 | 뜻 |
|---|---|---|---|
| `cast` | `Skill.cast` (`Misc.js`), 소환 네크 500 | clear 1-8 ④⑤ | 이번 틱에 실제로 시전했는가 |
| `moved` | setPosition | (기록만) | 이번 틱에 이동했는가 |
| `fail` | setPosition, 해머 게이트 | clear 1-8 ②③ | `"unreachable"`(갈 자리 없음) / `"moveFailed"`(이동 실패) |
| `must` | clear 1-7 | setPosition 2-3, 해머 게이트 | 이번 대상이 MUST인가 (판정 면제) |
| `monList` | clear 1-3 | setPosition 2-1 | 이번 틱 몬스터 목록 (위협 계산용, 다시 스캔하지 않으려고) |

**한 틱의 대화 예**
1. clear가 `tick`을 초기화하고 doAttack을 부른다.
2. 직업 파일이 setPosition을 부르고, setPosition이 갈 자리가 없으면 `fail = "unreachable"`로 적고 false를 반환한다.
3. 직업 파일은 0을 반환한다.
4. clear가 `fail`을 보고 SWEEP이면 즉시 버린다.

## 4. 실제 상황 따라가기

**A. 일반 소탕 `clear(25)`, 트인 곳에 몹 3마리**
- 1-3 스캔에서 3마리가 합류한다.
- 1-6에서 가장 가까운 몹을 고른다.
- 2-1에서 사거리 밖이면 접근이 필요하다. 2-3에서 바깥 링 정면 자리를 채택하고 `walkTo`로 이동한다.
- 시전하면 1-8 ⑤에서 시전 수가 오르고, 죽으면 다음 틱 1-4에서 빠진다.
- 모두 죽으면 1-5에서 종료 → 줍기, 상자.

**B. 벽(0x4) 너머 몹, 걷기**
- 2-3 (c)에서 몹 쪽 자리는 나에게서 벽 너머라 후보가 안 되고, 내 쪽 자리는 몹이 안 보여서 후보가 안 된다.
- 채택도 우회 후보도 없어서 `fail = "unreachable"`이 된다.
- 1-8 ②에서 즉시 버린다. 로그 `[AC] drop unreachable`.

**C. 강(0x1) 너머 몹**
- **원거리, 이미 사거리 안:** 2-1에서 이동이 필요 없으므로 바로 true → 제자리 공격.
- **근접, 몹 옆으로 가야 함:** 몹 옆 자리는 보이지만 직선이 강에 막혀 우회 후보가 된다. 2-3 (d)에서 나→몹 걷는 길이 직선 × 4 이하면 `moveTo`로 돌아가고, 넘으면 버린다.

**D. 보스 도주 `clear(35, "Lord De Seis")`**
- 1-3에서 보스가 MUST로 합류한다. 1-4 (a)에서 기준점이 보스를 따라간다.
- 보스가 시야에서 사라지면 lost 표시가 붙고, 칠 게 없어지면 1-5에서 마지막 위치로 찾아간다(최대 3번).
- 보스가 25 넘게 멀어지고 가까운 몹이 없으면 1-6 목줄로 보스를 먼저 쫓는다.
- 보스를 치는 동안 나에게서 10 안의 몹은 위험 반경으로 함께 처리한다.

**E. 박스 안 면역 몹 `clear(0, {box})`**
- 면역 몹에게 doAttack이 2를 반환하면 1-8 ①에서 deferred로 뒤로 보낸다.
- 다음 틱 1-6은 `nearestLive`(deferred 아닌 것)를 먼저 고르므로 나머지를 먼저 친다.
- 면역 몹만 남으면 다시 시도하고, 여전히 2면 잠깐 기다린다(다른 캐릭터가 잡을 때까지).
