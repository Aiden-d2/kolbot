# 퀘스트 플래그 표 (1.14d, D2MOO 대조)

`me.getQuest(번호, bit)`가 읽는 플레이어 퀘스트 기록의 bit별 의미.

- 쓰는 법: `me.getQuest(퀘스트 번호, bit)`.
- 반환값: 그 bit가 켜져 있으면 참. kolbot은 대부분 `if (me.getQuest(4, 0))`처럼 참·거짓으로 쓰고, 6곳은 `me.getQuest(7, 0) === 1`·`!== 1`로 비교한다(켜져 있으면 숫자 1이라는 전제). 꺼져 있을 때의 정확한 값은 미확인.
- 이 문서에서 사용하는 이름:
  - **MOO**: D2MOO(1.10f 복원 소스, ThePhrozenKeep/D2MOO).
  - **1.14d**: Game.exe 1.14d 역어셈블 결과. 셀의 `[0x...]`는 그 동작이 있는 1.14d 함수 또는 명령 주소다.
- 검증 방법: MOO의 플레이어 기록 쓰기 호출(`QUESTRECORD_SetQuestState` / `ClearQuestState` / `ResetIntermediateStateFlags`, 423개)을 퀘스트·bit별로 1.14d 동작과 대조했다. 대화 메시지 번호와 NPC는 MOO의 `Callback11_ScrollMessage`에서 확인했다.
- "MOO 대조" 칸:
  - **✔**: MOO와 일치한다.
  - **보강**: MOO에서 확인한 NPC·메시지 번호를 덧붙였다.
  - **MOO 기준**: MOO 코드로 확인한 동작을 적었다.
  - **1.14d만**: MOO에 없다(1.13 이후 추가로 추정).
- 플래그 이름(`QFLAG_*`)은 MOO `D2Constants.h`의 `D2C_OriginalQuestFlags` 순서이고, 각 이름의 값이 bit 번호다.
- 41번은 1.13에서 추가된 Akara 스탯·스킬 초기화(리스펙) 기록이다. 1.14d는 이 때문에 로드 처리 범위가 0~41(42개)이고, 액트 도입 퀘스트 필터 값도 42다(MOO는 0~40, 41).
- 미확인 항목은 `next_steps.md`.

## 퀘스트 기록 구조

| 항목 | 내용 | 근거 |
|---|---|---|
| 플래그 위치 | 퀘스트 번호 × 16 + bit (퀘스트당 16bit word) | 1.14d 0x65c310(읽기), 0x65c360(설정), 0x65c3a0(해제). MOO `D2QuestRecord.cpp` 같은 식 ✔ |
| bit 2~11 일괄 초기화 | `ResetIntermediateStateFlags`가 bit2(`STARTED`)~bit11(`CUSTOM7`)을 지움 | 1.14d 0x65c3e0. MOO `D2QuestRecord.cpp:31` ✔ |
| 로드 시 처리 | 모든 퀘스트의 bit13·14를 지우고, bit1이 있으면 bit15를 켬 | 1.14d 0x65c50e-0x65c54d (42개). MOO `CopyBufferToRecord` (41개) |
| bit 12 설정 | 클라이언트가 보낸 퀘스트 번호의 bit12를 켬 | 1.14d 0x54c9c0. MOO `PlrMsg.cpp` `Rcv0x58_QuestCompleted` ✔ |
| 퀘스트 번호 | 각 퀘스트 초기화 함수가 필터 값으로 저장 (예: 소환술사 = 13) | 1.14d 0x59c2d2. MOO `nQuestFilter` ✔ |
| 퀘스트 이름 | exe에는 없고 소스 파일명 문자열(예: a2q5.cpp)만 있음 | — |
| 저장 파일 | d2s의 퀘스트 영역(`Woo!`)은 난이도마다 96byte = word 48개이고, 0~41번이 이 순서대로 들어 있음 | D2CE `d2s_File_Format.md` |

## 공통 bit (퀘스트 0~41 전체)

| bit | MOO 이름 | 의미 | 동작 |
|---|---|---|---|
| 0 | `REWARDGRANTED` | 최종 완료. 보상형 퀘스트는 NPC 대화나 보상 사용 때 켜지면서 bit1이 꺼진다. 일부 퀘스트는 달성 즉시 켜진다 | 퀘스트별 |
| 1 | `REWARDPENDING` | 요구사항 달성, 보상 대기. **보상을 받으면 꺼지므로 "달성함"과 같은 뜻이 아니다** | 퀘스트별 |
| 2 | `STARTED` | 퀘스트 시작(일부 퀘스트는 쓰지 않음) | 퀘스트별 |
| 3 | `LEAVETOWN` | 이름은 MOO 기준이고, 실제 의미는 퀘스트마다 다르다 | 퀘스트별 |
| 4 | `ENTERAREA` | 위와 같다 | 퀘스트별 |
| 5~11 | `CUSTOM1`~`CUSTOM7` | 퀘스트마다 다르다 | 퀘스트별 |
| 12 | `UPDATEQUESTLOG` | 퀘스트 로그를 닫음(클라이언트 보고) | 클라이언트 패킷을 받으면 설정 [0x54c9c0] |
| 13 | `PRIMARYGOALDONE` | 이번 게임에서 목표 달성 | 로드 시 삭제 [0x65c50e] |
| 14 | `COMPLETEDNOW` | 이번 게임에서 퀘스트가 끝났지만 이 캐릭터는 크레딧을 받지 못함(bit0·1 없음) | 로드 시 삭제 [0x65c50e] |
| 15 | `COMPLETEDBEFORE` | 로드할 때 bit1이 있었음(이전 게임에서 보상을 받지 않음) | 로드 시 bit1이 있으면 설정 [0x65c538] |

- 각 퀘스트 표에는 동작이 있는 bit만 적었다. 빠진 bit는 1.14d에서 그 퀘스트의 그 bit를 플레이어 기록에 쓰는 코드를 찾지 못한 것이다.
- bit12~15는 위 공통 동작 외에 그 퀘스트에만 있는 추가 동작만 적었다.
- 방장 기록과 크레딧:
  - 게임 시작 처리는 방을 만든 첫 플레이어에게만 돈다.
  - 그 플레이어 기록에 bit0 또는 bit15가 있으면 그 게임에서 해당 퀘스트가 꺼진다(MOO `Quests.cpp` `QUESTS_SequenceCycler`).
  - 자세한 내용은 `D2BS_Structure.md` "확인된 사실"의 퀘스트 크레딧·방장 규칙.
